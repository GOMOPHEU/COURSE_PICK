## 2. 서버에서 남은 것

| 순서 | 항목 | 내용 |
|---|---|---|
| 1 | 코스 조립 + `/recommend` 연결 | 칸마다 후보 수집, 매칭표 조회, 영업시간 판정, 점수, 한 곳 선택. 적격 후보가 3곳 미만이면 반경 확장. 구글 검증은 점수순으로 5곳씩. 마지막 장소는 남는 시간만큼 체류 연장 |
| 2 | 카카오 경로 API 시간 검증 | 도보 추정값을 확정된 코스의 구간 2~3개만 실제 값으로 교체 |
| 3 | 동행 규칙 적용 | 가족: 술집 제외, 이동 15분 이하. 나머지 동행은 규칙 확정 후 |
| 4 | 시나리오 테스트 | `docs/scenarios`의 가족 토요일, 연인 평일 저녁, 10대 친구 화요일, 시간 입력 오류 케이스 |
| 5 | 구글 호출 상한 | 무료 한도(월 약 1,000건) 보호용 |
| 6 | Gemini 연결 | 기본 흐름 완성 후(11/25 이후). 결제 안 된 프로젝트에서 품질 확인 호출 1회 |
| 7 | check19 흐름 팀 공유 | 공유 여부 확인 필요 |

## 4. 문서와 정리 사항

- 할일 목록 v2에 "Node 서버", "OpenAI"로 적힌 곳을 Spring Boot, Gemini로 고치기 (팀 합의 필요)
- 후보 검색 방식 변경 내용을 문서 4-1절에 반영하기. 문서는 "반경 690m, 부족하면 1,000m 한 번"인데 구현은 "거점 ±100m 사각형에서 단계별 확장"으로 바꿈. 밀집 테마에서는 카카오 한도 때문에 반경 확장이 효과가 없다는 이유
- `server/run_log.txt`가 영업시간 커밋에 실수로 올라감. 키는 없음. 파일 삭제와 `.gitignore` 추가 필요
- 수집 파일(`kakao_all.json`, `reviews_dump.json`) 사용 후 삭제, 공유 금지
- API 키는 환경변수로만 사용: `KAKAO_REST_API_KEY`, `GOOGLE_PLACES_API_KEY`, `GEMINI_API_KEY`. 카카오 키는 팀원3이 재발급, 구글 키는 팀원2가 재발급
