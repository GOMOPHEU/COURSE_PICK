# 점검·시연용 시나리오

같은 시나리오를 11/25 점검, 정량평가, 시연 영상에 모두 쓴다.
요청 본문은 `docs/scenarios/` 폴더의 JSON 파일이고, 보고서 5.4절 필드 이름을 따른다.

11/26 수정: 서버 구현(11/25, `server/진행현황.md`)에 맞춰 기대값을 고쳤다. 바뀐 곳은 각 항목에 "(11/26 수정)"으로 표시했다.

## 시나리오 1. 가족 · 토요일 오후 · 역사 + 카페

| 항목 | 값 |
|---|---|
| 요청 파일 | `s1-family-saturday.json` |
| 출발 | 안국역, 2026-11-28(토) 14:00 → 18:00 (240분) |
| 이동 | 대중교통 |
| 테마 | 역사, 카페 |
| 동행 | 가족 4명 |

확인할 것
- 술집(분류가 "음식점 > 술집"이거나 이름에 이자카야·호프·포차·앤바·사카바·주점)이 후보에 한 곳도 없다
- 모든 구간 이동이 15분 이하다. 다만 서버는 후보를 고를 때 추정 이동시간을 쓰므로, 경로 검증 뒤 실측이 15분을 조금 넘을 수 있다. 넘으면 시간과 구간을 기록한다 (11/26 수정)
- 경복궁·창덕궁 같은 대형 궁은 체류 90분으로 잡힌다
- 총 소요시간이 240분 이하이고, 여유/빠듯함이 표시된다
- 토요일이라 궁 휴관이 없으므로 경복궁·창덕궁이 후보에 들어올 수 있다

## 시나리오 2. 연인 · 평일 저녁 · 전시·문화 + 산책 + 맛집

| 항목 | 값 |
|---|---|
| 요청 파일 | `s2-couple-weekday-evening.json` |
| 출발 | 경복궁역, 2026-12-03(목) 17:00 → 21:00 (240분) (11/26 수정: 11/26이 지나므로 다음 목요일로 바꿈) |
| 이동 | 도보 |
| 테마 | 전시·문화, 산책, 맛집 |
| 동행 | 연인 2명 |

확인할 것
- 출발 시각 17:00이 저녁 식사 시간대 시작과 같아서 첫 장소로 맛집(저녁 식사)이 바로 들어간다 (11/26 수정)
- 저녁 식사는 17:00~19:30 사이에 시작한다. 서버 설정 `mealWindows.dinner` 기준이다 (11/26 수정)
- 도착 시각 + 체류시간이 영업 종료를 넘는 곳(예: 18시에 닫는 전시관)은 빠진다
- 모든 구간이 도보(legs의 mode가 walk)다
- 코스가 2개만 나올 수 있다. 문화 후보가 많아 요청당 구글 호출 한도(30건)에 걸리기 때문이며 오류가 아니다 (11/26 추가)

참고: 연인 저녁 규칙(17시 이후 카페·전시·문화·산책 우선)은 설정 파일에만 있고 서버 코드에는 아직 적용되지 않았다. 동행 규칙이 확정되면 다시 확인한다 (11/26 추가)

## 시나리오 3. 10대 친구 · 화요일 오전 · 역사 + 쇼핑 · 도보 최소화

| 항목 | 값 |
|---|---|
| 요청 파일 | `s3-teen-friends-tuesday.json` |
| 출발 | 광화문역, 2026-12-01(화) 10:00 → 13:00 (180분) |
| 이동 | 도보 |
| 테마 | 역사, 쇼핑 |
| 동행 | 친구 3명, 10대, 도보 최소화 |

확인할 것
- 화요일 휴궁인 경복궁이 빠진다. 서버 휴관일 설정(`closedDays`)과 공식 운영시간 파일에 화요일로 들어가 있다 (창덕궁은 화요일 관람 가능)
- 종묘도 화요일 휴관이지만 서버 휴관일 설정과 공식 운영시간 파일에 아직 없어서 구글 영업시간으로만 판정된다. 결과에 종묘가 나오면 휴관일 설정에 추가해 달라고 서버 담당에게 요청한다 (11/26 수정)
- 모든 도보 구간이 10분 이하다. 시나리오 1과 같은 이유로 실측이 조금 넘을 수 있다(서버 진행현황 예: 11분). 넘으면 기록한다 (11/26 수정)
- 10대라 술집 제외 규칙이 적용된다

## 오류 확인용

| 요청 파일 | 내용 | 기대 결과 |
|---|---|---|
| `e1-invalid-time.json` | 종료 시각(14:00)이 출발 시각(15:00)보다 빠름 | 400 INVALID_INPUT, 앱은 설문 입력 오류 표시 |

현재 서버(11/25)는 400을 돌려주지만 본문이 `{"error": "종료 시각은 출발 시각보다 늦어야 합니다"}`뿐이고 `INVALID_INPUT` 코드가 없다. 서버에서 코드를 맞추기로 했다(서버 진행현황 2-6). 그 전까지는 상태 코드 400과 메시지로 확인한다 (11/26 추가)

## 날짜 주의 (11/26 수정)

서버가 지난 날짜를 막지는 않는다. 그러나 구글 영업시간은 오늘 이후 날짜만 판정하므로, 지난 날짜로 요청하면 영업시간이 "모름"이 되고 영업시간을 모르는 곳은 제외하는 설정(`planning.requireKnownHours`) 때문에 장소가 대부분 빠진다. 요청 날짜는 항상 오늘 이후의 같은 요일로 바꾼다. 구글 영업시간은 오늘부터 7일 안의 날짜일 때 가장 정확하다.
